# Images

Every file here is generated by `design/build-assets.py`. Re-run it from the
project root after changing any of the masters:

    python design/build-assets.py

Do not hand-edit these files — the next run overwrites them.

## Masters

| Master | What it is |
| --- | --- |
| `design/logo-colour.jpeg` | The circular mark: the three dots, `</>` and the hand |
| `design/banner.jpeg` | The wide lockup with the full name |
| `design/logo-master.png` | The original ink drawing, still the source of the standalone hand |

## Generated

| File | Size | Where it appears |
| --- | --- | --- |
| `logo-mark.png` / `.webp` | 320 x 316 | The mark in the header, the bands and the footer |
| `logo-mark-large.png` / `.webp` | 720 x 711 | The same mark for slides, print and the JSON-LD `logo` |
| `banner.png` / `.webp` | 1600 x 569 | The wide lockup, wherever the full name is wanted as artwork |
| `hand.png` / `.webp` | 894 x 1200 | The hero on the home page, and the 404 page |
| `og-image.png` | 1200 x 630 | The social sharing card in every page's meta tags |

## Notes

- The mark's PNG and WebP both carry an **alpha channel**, and the area
  outside the disc is transparent. That is why one file works on the cream
  page, on the navy bands and in the footer, and why there is no longer an
  inverse variant. The transparency is cut with a flood fill inwards from the
  corners rather than a "white becomes transparent" rule, which would
  otherwise punch a hole through the cream inside the disc.
- `hand.png` is tinted `#062350`, the navy in `--color-ink`, so the drawing
  belongs to the same identity as the type around it.
- The masters are JPEGs, so they carry compression noise that a straight PNG
  would store faithfully and expensively. Every export is quantised to a small
  palette first, which is what keeps the mark at 23 KB rather than 560 KB.
- Only `index.html` and `404.html` use `<picture>` to prefer the WebP — those
  are the pages with the large hand. Everywhere else the `<img>` points at the
  PNG, which is small enough that a second request is not worth it.
- The `width` and `height` attributes in the HTML match the table above. If a
  file is regenerated at a different size, update the attributes too or the
  page will shift while it loads.
- Favicons in `../favicon/` are cut from the same mark, composited onto the
  cream ground rather than left transparent, because iOS fills transparent
  touch icons with black.
